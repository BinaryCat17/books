# books

Сканы технических книг → Markdown. Три пути обработки и раннер, который умеет
снимать GPU в аренду под любую задачу, а не только под эту.

```
books/
├── src/booksmith/
│   ├── remote/          аренда и запуск ЧЕГО УГОДНО на арендованной машине
│   ├── jobs/paddleocr/  конкретная задача: PDF -> Markdown
│   ├── engines/         локальные движки (OCR-слой из PDF, Mistral)
│   └── cli.py           books <команда>
├── infra/image/         Dockerfile образа (сборка в GitHub Actions)
├── bench/               25 страниц для сравнения движков
├── runs/                журнал прогонов (ledger.jsonl)
├── raw/                 оригиналы, не версионируются
└── processed/           результаты, не версионируются
```

## Контракт задачи

Раннер знает ровно три вещи: **входные файлы, команду и каталог с результатом**.
Ничего про PDF и OCR в `remote/` нет — иначе следующая ML-задача снова
потребовала бы переписывать аренду.

```python
JobSpec(
    name="test25",
    image="ghcr.io/binarycat17/paddleocr-vl:offline",
    command="bash run.sh input.pdf outputs",
    inputs={"книга.pdf": "input.pdf", "run.sh": "run.sh"},
    outputs="outputs",          # тянется к нам ПО ХОДУ работы, не в конце
    budget_usd=1.00,            # жёсткий потолок: достигнут — машина гибнет
)
```

## Установка

```bash
python3 -m venv tools/venv
tools/venv/bin/pip install -e .
tools/venv/bin/vastai set api-key <КЛЮЧ>        # console.vast.ai/account
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_vast -N ''
```

Секреты — в `.env` в корне (режим 600, не версионируется), образец в
`.env.example`. Впиши их сам, в своём терминале.

## Запуск

```bash
books offers                              посмотреть рынок, ничего не арендуя
books ocr bench/test25.pdf bench/paddleocr
books ocr raw/книга.pdf processed/книга --keep     оставить машину
books ocr raw/книга.pdf processed/книга --reuse 12345
books ls                                  что арендовано прямо сейчас
books down 12345 | books reap             убить инстанс / прибрать всё
books ledger                              журнал прогонов и оценки по нему
```

Полезные флаги `ocr`: `--gpu RTX_5090`, `--max-dph`, `--budget`, `--timeout`,
`--machine <id>` (прогретая машина), `--image`, `--dry-run`.

## Как выбирается машина

Не по цене за час. Ранжирование считает **полную стоимость прогона**:

| составляющая | почему |
|---|---|
| выкачивание образа | одиночный поток на слой; заявленная полоса реализуется процентов на десять |
| распаковка | 5.9 ГБ сжатого → ~18 ГБ на диске; медленный диск стопорит старт |
| **трафик** | цена входящего трафика ненулевая у **всех** офферов: от $0.4 до $29.3 за ТБ |
| аренда | собственно $/час |

Разница не косметическая: на худшем оффере рынка трафик даёт $0.23 при $0.35
аренды — 40% счёта в поле, которое ранжирование по `dph_total` не видит.

Прогретые машины берутся из журнала автоматически: кеш docker живёт на
физической машине, и повторная аренда там же убирает почти весь холодный старт.

## Деньги не могут утечь

Уничтожение продублировано трижды, потому что каждый способ по отдельности
однажды подвёл:

1. `finally` — на любом выходе, включая исключение;
2. перехват SIGINT/SIGTERM — иначе процесс умирает мимо `finally`;
3. сторожевой поток по бюджету — на случай, если основной залип в ssh.

Плюс проверка: после `destroy_instance` список инстансов запрашивается заново.
Раньше здесь дёргался CLI, который **возвращал 0, даже когда отказывался
уничтожать**, и скрипт рапортовал об успехе, пока шли деньги.

## Образ

Официальный образ пайплайна не содержит vllm и torch вовсе — только
`paddlepaddle-gpu`, поэтому VLM считался в процессе и еле полз. Свой образ
(`infra/image/Dockerfile`, сборка в GitHub Actions) кладёт vLLM и пайплайн
вместе и разносит установки по слоям примерно по гигабайту: у официального один
слой на 3.69 ГБ, то есть 62% объёма тянутся в один поток и распаковываются
одним ядром.

Подробности и полный список граблей vast.ai — в `docs/vast-notes.md`.
