# vast.ai + PaddleOCR-VL

Аренда GPU на один прогон: снять карту → распарсить книгу → забрать результат →
убить инстанс. Инстанс уничтожается в блоке `finally`, то есть при успехе,
при ошибке и по Ctrl-C.

## Что и почему выбрано

**Образ `*-offline`.** У PaddleOCR есть два варианта образов, и в offline-версию
веса вшиты внутрь. Это и есть «заранее загрузить модель»: контейнер стартует, ничего
не скачивая. Отдельный том для весов не нужен.

**Про тома vast.ai.** Volume физически привязан к машине, на которой создан, и
подключается только к инстансам на ней же. То есть «положить данные на vast.ai»
означает «навсегда привязаться к одному хосту» — теряется возможность брать
самое дешёвое предложение, а при уходе хоста данные оказываются заперты. Для нашей
полезной нагрузки (книга 87 МБ) это не окупается: заливка занимает секунды.

**Что действительно долго — это выкачивание docker-образа** (CUDA + vLLM + веса,
десятки гигабайт) из реестра Baidu в Пекине. Именно поэтому в поиске стоит фильтр
`inet_down`, а не цена в одиночку: разница между хостом на 200 и на 2000 Мбит
влияет на время запуска сильнее, чем цена за час.

**Прогрев хоста.** Скачанный образ остаётся в кеше docker на физической машине.
После первого прогона запомни `machine_id` из лога и запускай следующие прогоны
с `--machine <id>` — образ уже там, старт занимает около минуты.

**Почему по умолчанию RTX 4090, а не 5090.** Модель весит 0.9B, ей нужно ~3 ГБ
VRAM — 32 ГБ против 24 ГБ не дают ничего. При этом sm_120 сборки PaddlePaddle
вендор проверял только на RTX 5070, совместимость с остальными Blackwell
официально не подтверждена, а 4090 — основной оттестированный путь и по медиане
дешевле. 5090 запускается флагом `--gpu RTX_5090`, скрипт сам подставит образ
`-sm120`.

## Разовая настройка

Ключ `~/.ssh/id_ed25519_vast` уже создан отдельно от github-овских. Осталось два шага:

```bash
tools/venv/bin/vastai set api-key <КЛЮЧ>        # ключ из console.vast.ai/account
tools/venv/bin/vastai create ssh-key "$(cat ~/.ssh/id_ed25519_vast.pub)"
```

Зависимости (`vastai` в том числе) ставятся так:

```bash
tools/venv/bin/pip install -r tools/requirements.txt
```

## Запуск

```bash
cd tools/vast

# посмотреть предложения, ничего не арендуя
../venv/bin/python launch.py --dry-run --gpu RTX_4090

# тест на 25 страницах — тех же, что гонялись через Mistral
../venv/bin/python launch.py ../../bench/test25.pdf ../../bench/paddleocr

# вся книга
../venv/bin/python launch.py \
    ../../raw/Machine_tool_reconditioning_and_applications_of_hand_scraping_Edward.pdf \
    ../../processed/Machine_tool_reconditioning_..._paddleocr

# повтор на прогретой машине
../venv/bin/python launch.py ... --machine 12345

# если что-то осталось висеть
../venv/bin/python launch.py --reap
```

Полезные флаги: `--max-dph` потолок цены, `--min-down` минимальный канал,
`--disk` размер диска, `--keep` не убивать инстанс (для отладки — **тратит деньги**).

## Как устроено

| файл | где исполняется | что делает |
|---|---|---|
| `launch.py` | локально | поиск предложения, аренда, заливка, запуск, скачивание, уничтожение |
| `mirror_image.py` | локально | разово перекладывает образ из реестра Baidu в GHCR |
| `remote_job.sh` | на инстансе | поднимает vLLM-сервис, ждёт health, зовёт парсер, собирает логи |
| `remote_parse.py` | на инстансе | `PaddleOCRVL.predict` → `restructure_pages` → markdown + json |

## Зеркало образа

Выкачивание из реестра Baidu в Пекине занимало 8–14 минут и срывалось в ретраи.
Из GHCR тот же образ приходит с ближайшей точки CDN за 2–3 минуты.

```bash
# один раз, в своём терминале — токен не должен попасть в переписку
umask 077
echo 'GHCR_USER=логин'   >> tools/.env
echo 'GHCR_TOKEN=ghp_..' >> tools/.env    # github.com/settings/tokens, write:packages

../venv/bin/python mirror_image.py
```

Копирование идёт `skopeo`-ом напрямую между реестрами через арендованный инстанс
с каналом 10 Гбит — 30 ГБ не проходят через твой домашний канал. Стоит ~$0.05.
Токен передаётся в `skopeo login --password-stdin`, то есть не появляется ни в
аргументах команды, ни в onstart-скрипте (его vast.ai хранит и показывает в консоли).

После копирования один раз сделай пакет публичным в вебе, иначе vast не сможет его
скачать без авторизации: *github.com/users/ЛОГИН/packages → пакет → Package settings
→ Change visibility → Public*.

Дальше:

```bash
../venv/bin/python launch.py книга.pdf выход/ \
    --image ghcr.io/логин/paddleocr-vl:offline
```

`restructure_pages(merge_tables=True, concatenate_pages=True)` склеивает таблицы,
переходящие на следующую страницу, и абзацы через разрыв страницы — то, что для
PyMuPDF-конвейера писалось руками.

Если vLLM-сервис не поднимется, `remote_job.sh` не падает, а переключается на
инференс в процессе — медленнее, но прогон доводится до конца, и в `run.json`
видно, какой путь сработал.

## Экономика

RTX 4090 + vLLM дают около **1.15 страниц/с** (замер авторов PaddleOCR-VL на
OmniDocBench). На 539 страниц это порядка 8 минут счёта. Основное время — не
счёт, а выкачивание образа.

| статья | время | цена при $0.36/час |
|---|---|---|
| выкачивание образа (холодный хост) | 5–15 мин | $0.03–0.09 |
| выкачивание образа (прогретый хост) | ~1 мин | $0.006 |
| парсинг 539 страниц | ~8–15 мин | $0.05–0.09 |
| **итого холодный старт** | **15–30 мин** | **$0.09–0.18** |

Для сравнения: те же 539 страниц через Mistral OCR 4 — $2.16.

## Грабли vast.ai, на которые мы уже наступили

Всё это исправлено в коде, но если будешь писать своё — знай.

**`destroy instance` требует подтверждения и при отказе возвращает 0.**
Неинтерактивный вызов печатает `Aborted`, код возврата 0, инстанс продолжает
работать. Самая дорогая из ловушек: скрипт рапортует об уничтожении, а деньги
идут. Нужен флаг `-y`, а проверять — **повторным запросом списка**, а не кодом
возврата.

**Ключ, зарегистрированный на аккаунте, не попадает в инстанс.**
`vastai create ssh-key` только кладёт его в аккаунт. Чтобы подключиться, нужен
`vastai attach ssh <instance_id> "<pubkey>"` для каждого инстанса. Иначе
`Permission denied (publickey)` — и узнаёшь ты об этом после того, как выкачал
30 ГБ образа.

**sshd загоняет вход в tmux и глотает команду.**
`ssh host 'команда'` печатает `no sessions / open terminal failed` и ничего не
выполняет. Лечится `touch /root/.no_auto_tmux` в onstart-скрипте.

**`vastai execute` не годится для произвольных команд** — белый список,
на обычную команду отвечает `400: Invalid command given`.

**Поле `ssh_host` заполняется не всегда**, хотя `vastai ssh-url` при этом
отдаёт адрес нормально. Ждать его в цикле — значит молча висеть до таймаута.

**У образов бывает нет `/workspace`.** Не полагайся на него, создавай свой
каталог.

## Чего скрипт не делает

Первый прогон — разведка. Не проверено на живом железе: поднимется ли vLLM-сервис
и пайплайн в одном контейнере (официальный деплой разносит их на два контейнера
через docker compose из-за конфликта версий `transformers`, а инстанс vast.ai сам
по себе контейнер). Ради этого и сделан запасной путь с инференсом в процессе, и
ради этого первый запуск идёт на 25 страницах, а не на всей книге.
