# booksmith

Конвейер, который превращает сканы книг в размеченный Markdown. Распознавание
(PaddleOCR-VL на арендованной GPU) запускается командой `books ocr`, дальше
результат конвертируется в html/epub/fb2/pdf.

## Если просят перевести, пересказать или проверить книгу

**Сначала прочитай `work_instruction.md` целиком, потом берись за текст.**

Это не формальность. Разбор сделан со сканов и содержит пометки достоверности;
без них ты будешь чинить числа так же уверенно, как чинишь слова, а числа в
справочнике чинить нельзя. В инструкции сказано, что означает каждая пометка,
что можно править свободно, а что только помечать, и как сверить значение с
оригиналом.

Тот же файл вставляют как готовый промт в чат, если у модели нет доступа к
файлам.

## Где лежит книга

Каждый прогон кладёт результат в `processed/<имя>/`. Наверху только готовое,
всё черновое — в `passes/`:

```
processed/<имя>/
  <книга>.md          <- готовый текст, с ним и работай
  <книга>.toc.md      <- оглавление с номерами строк книги
  report.md           <- что в этом разборе неполно, числами
  imgs/               <- картинки: tbl_*.jpg — вырезки таблиц из скана
  <книга>.html .epub .fb2 .pdf    <- то же самое для чтения человеком
  run.json            <- из какого pdf, сколько страниц, проходов, стоило
  passes/
    1/  pages/ book/ job.log      <- ЧЕРНОВИК: постраничный вывод, основа
    2/  pages/ job.log            <- ЧЕРНОВИК: свидетель
    3/  …
```

`<книга>` — имя исходного pdf. Так что в `processed/book-new/` лежит
`Machine_tool_reconditioning_..._Edward.md`, а не `book.md`: имя каталога
оператор задавал наспех, а книга должна называться книгой. Точное имя
записано в `run.json` полем `stem` — бери оттуда или просто читай
единственный `*.md` в корне.

Сейчас в работе `processed/book-new/` — справочник по восстановлению станков,
539 страниц. Каталог `processed/` не версионируется.

## Что читать и чего не читать

- **Читай `<книга>.md` в корне каталога.** Это единственный готовый текст:
  заголовки собраны, таблицы сшиты через разрывы страниц, переносы склеены,
  расхождения между чтениями помечены — сколько чего, сказано в `report.md`.
- Для перевода и пересказа бери **по главам**, а не всю книгу разом: в
  справочнике около 440 тыс. токенов. Границы глав — в `<книга>.toc.md`, там у
  каждой стоят номера строк; читай кусок по ним.
- **Начни с `report.md`.** Он говорит числами, что в этом разборе собралось, а
  что нет: сколько глав, где нарушен порядок чтения, сколько подписей стоит не
  у своих картинок. Пишет его код (`books restructure`), не человек; прогон
  зовёт его сам.
- **Не читай `passes/`.** Это черновик: постраничный вывод до сборки. Там нет
  ни склеенных через разрыв страницы таблиц, ни заголовков, ни пометок
  расхождения. Он выглядит как текст книги и таковым не является.
  `passes/1/pages/*.json` нужны только конвейеру — из них `books restructure`
  берёт разметку структуры.
- **Картинки открывай по необходимости**, по ссылке из текста. Перед каждой
  таблицей стоит `<!-- скан таблицы: imgs/tbl_….jpg -->` — вот это открывай,
  когда сверяешь числа. Путь бери из комментария, а не склеивай по
  образцу. Вырезок 41, весят вместе полтора мегабайта.
- **Не читай `.html`, `.epub`, `.fb2`, `.pdf`.** Это тот же текст, собранный
  для человека; html — около 2 МБ разметки вокруг того же содержимого,
  остальные весят по 80–100 МБ. Ничего нового в них нет.
- **Не читай `imgs/` подряд.** 768 файлов, 81 МБ.
- **Не читай `*.md.before-restructure`.** Это слепок до сборки структуры, он на
  глаз неотличим от книги и тем опаснее тяжёлых форматов: те хотя бы не
  выглядят текстом. Нужен он только для сверки «до и после».

## Команды, которые не стоят денег

Всё, что можно посчитать местно, считается местно — правку, которую нельзя
применить к уже оплаченному разбору, применяют к нему никогда:

```
books merge processed/<имя>        пересобрать книгу из проходов заново
books restructure processed/<имя>  пересобрать заголовки, оглавление, отчёт
books convert processed/<имя>      собрать html/epub/fb2/pdf
books tidy processed/<имя>         перевести старый разбор в нынешнюю раскладку
books progress                     лента этапов последнего прогона
```

## Код

`src/booksmith/` — CLI (`cli.py`), аренда и прогон на удалённой машине
(`remote/`), задание распознавателя (`jobs/paddleocr/entrypoint.py`), сборка
структуры (`structure.py`), сборка форматов (`convert.py`, `merge.py`).

`structure.py` — местный шаг без карты: раскладывает `book.md` по меткам
структуры из `pages/*.json` (`doc_title`, `header`, `paragraph_title`,
`figure_title`), склеивает переносы, пишет `toc.md` и `report.md`. Прогон
зовёт его сам; повторить можно командой `books restructure processed/<имя>`.
Шаг идемпотентен — второй запуск не меняет ни байта.

Замеры, отвергнутые гипотезы и разбор ошибок распознавания — в
`docs/ocr-notes.md`; там же объяснено, откуда взялись числа в
`work_instruction.md`.
